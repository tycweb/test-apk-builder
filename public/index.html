📦 How to zip your project

The build will fail (or silently pick up the wrong files) if the zip isn't structured right. Follow this and you'll be fine.

  • 1
    Zip the project folder itself — the one that directly contains settings.gradle (or settings.gradle.kts) and build.gradle. If those files are one level deeper inside the zip, the build can't find your project.
  • 2
    It's fine if the zip has one single top-level folder (like MyApp.zip → MyApp/settings.gradle) — that's the normal case and it's handled automatically.
  • 3
    Include the Gradle wrapper (gradlew, gradlew.bat, and the gradle/ folder) if your project has one, so the build uses the exact Gradle version you built with.
  • 4
    Have a custom CI workflow? Include your own .github/workflows/*.yml with a workflow_dispatch trigger and it'll be used automatically. Otherwise a sensible default (assembles a debug APK) is generated for you.
  • 5
    Leave out build output — build/, .gradle/, *.apk — it's regenerated fresh and just bloats the upload.
Good structure MyApp.zip
└ MyApp/
  ├ settings.gradle
  ├ build.gradle
  └ app/
Avoid Zipping only the app/ folder, or a folder several levels above the project root with lots of unrelated content mixed in.
